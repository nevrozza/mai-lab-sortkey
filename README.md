# ЛР. Сортировка таблицы по ключу
### Shell sort + бинарный поиск

В проекте реализована программа для работы с таблицей записей вида `ключ - значение`. Ключ хранится как `double`, значение - строка фиксированного размера.

Программа умеет вводить данные вручную, запускать автоматические тесты, сортировать таблицу методом Шелла и выполнять бинарный поиск по ключу уже после сортировки.

## Код

- [**main.c**](./main.c) - основной CLI-цикл
- [**solution/solution.c**](./solution/solution.c) - `shell_sort` и `binary_search`
- [**solution/cli.c**](./solution/cli.c) - печать таблицы и запуск теста сортировки
- [**vector/item.h**](./vector/item.h) - структура записи `Item`
- [**vector**](./vector/vector.h) – динамический массив для хранения записей

# Отчет по лабораторной работе по курсу "Алгоритмы и структуры данных"

**Тема:** Сортировка и поиск в таблице.

**Цель:** Реализовать сортировку таблицы по ключу и поиск элемента в отсортированной таблице.

**Задание:** Составить программу для сортировки таблицы по ключу и дальнейшего поиска записей по этому ключу.

## Идея и метод решения

Каждая запись таблицы описывается структурой `Item`:

```c
#define MAX_STR 100

typedef struct Item {
    double key;
    char value[MAX_STR];
} Item;
```

Для хранения записей используется динамический массив `vector`. Это удобно для сортировки: элементы лежат подряд в памяти, поэтому `shell_sort` может работать с обычным массивом через `get_raw_array`.

Сама сортировка реализована как обобщенная функция:

```c
void shell_sort(void *base, size_t nmemb, size_t size,
                int (*compar)(const void *, const void *));
```

То есть сортировка не привязана напрямую к `Item`: она получает указатель на массив, количество элементов, размер одного элемента и компаратор. В этой работе для таблицы используется `item_compare_item`, который сравнивает записи по полю `key`.

После сортировки запускается бинарный поиск:

```c
void *binary_search(const void *key, void *base, size_t nmemb, size_t size,
                    int (*compar)(const void *, const void *));
```

Он ищет запись по ключу в уже отсортированном массиве. Для этого используется отдельный компаратор `item_key_compare`, который сравнивает ключ поиска с ключом записи.

## Структура программы

Логически проект можно разделить на несколько частей:

- `main.c` отвечает за меню, ввод данных и запуск тестов
- `vector` хранит динамический массив записей
- `Item` описывает одну запись таблицы
- `item_compare_item` сравнивает две записи по ключу
- `item_key_compare` сравнивает ключ поиска с записью
- `shell_sort` сортирует массив записей
- `binary_search` ищет запись по ключу в отсортированном массиве
- `cli` печатает таблицу до и после сортировки

В ручном режиме пользователь вводит пары `ключ значение`. Ввод завершается, когда вместо числового ключа вводится строка. В режиме автоматических тестов программа сама создает три набора: уже отсортированный, обратный и случайный.

## Алгоритм сортировки Шелла

1. Создается временный буфер размером с один элемент массива
2. Начальный шаг `gap` берется равным половине количества элементов
3. Для каждого `gap` элементы сравниваются не подряд, а через этот шаг
4. Если элемент должен стоять раньше, блок памяти сдвигается через `memcpy`
5. В освободившуюся позицию записывается временно сохраненный элемент
6. После прохода шаг уменьшается в два раза
7. Когда `gap` становится равным нулю, сортировка завершается

Такой вариант удобен тем, что работает не только с `Item`, а с любыми элементами одинакового размера. Для этого и нужны `void *`, `size_t size` и функция-компаратор.

## Алгоритм бинарного поиска

1. Устанавливаются границы поиска: `l = 0`, `r = nmemb`
2. Пока левая граница меньше правой, берется середина
3. Ключ поиска сравнивается с элементом в середине
4. Если ключи равны, возвращается указатель на найденную запись
5. Если искомый ключ больше, поиск продолжается справа
6. Если искомый ключ меньше, поиск продолжается слева
7. Если границы сошлись, возвращается `NULL`

## Тонкости реализации

При реализации нужно учитывать:

- запись `Item` должна перемещаться целиком
- компаратор для сортировки и компаратор для поиска отличаются
- бинарный поиск ожидает уже отсортированный массив
- `shell_sort` работает с `void *`, поэтому сдвиги по памяти нужно делать через размер элемента
- для копирования элементов используется `memcpy`
- в ручном режиме ввод заканчивается не отдельной командой, а нечисловым ключом

> [!NOTE]
> В `main.c` после поиска есть очистка состояния ввода. Это нужно, потому что выход из поиска происходит по нечисловому вводу, а значит в `stdin` остается мусор для следующего чтения.

Кратко про обработку ошибок: программа учитывает пустую таблицу, некорректный ввод ключа и ситуацию, когда искомый ключ отсутствует в таблице.

1. Реализация структуры `Item`
2. Реализация динамического массива для хранения записей
3. Реализация компараторов для сортировки и поиска
4. Реализация обобщенной сортировки Шелла
5. Реализация бинарного поиска
6. Реализация CLI-режима для ручного ввода
7. Реализация автоматических тестов
8. Проверка поиска после сортировки

Примеры тестов:

| **Сценарий** | **Что проверяется** |
|:------------|:--------------------|
| уже отсортированный набор | сортировка не ломает правильный порядок |
| обратный порядок | сортировка переставляет все элементы |
| случайные ключи | работа на обычном наборе данных |
| одна запись | минимальный непустой набор |
| `N <= 0` в автотестах | обработка пустой таблицы |
| поиск существующего ключа | бинарный поиск возвращает запись |
| поиск отсутствующего ключа | вывод сообщения, что ключ не найден |
| выход из поиска буквами | корректное завершение режима поиска |

## Сложность

Для сортировки Шелла сложность зависит от последовательности шагов. В этой реализации шаг каждый раз делится на два.

| **Операция** | **Сложность** |
|:------------|:--------------|
| чтение данных | `O(n)` |
| сортировка Шелла | зависит от входных данных, в худшем случае может быть около `O(n^2)` |
| бинарный поиск | `O(log n)` |
| вывод таблицы | `O(n)` |
| память для временного элемента сортировки | `O(1)` без учета массива данных |
